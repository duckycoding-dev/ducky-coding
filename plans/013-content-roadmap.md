## Why this matters

The site is a finished, over-engineered platform serving 3 posts, all from
June 2025. The owner's stated goal: a gateway for showcasing projects and
knowledge. The owner's stated blocker: "writing about common stuff has no
point nowadays." The audit's answer, grounded in this repo: commodity
explainers are indeed dead (an LLM answers them better), but **evidence-based
writing is not** — and this repo already contains both the proof and a
backlog of un-mined material.

## Evidence (all verified in-repo)

1. **Stated-but-undelivered**: the launch post
   (`src/content/posts/welcome-to-duckycoding.mdx:131-141`) promises six
   content types — quick guides, in-depth articles, **project showcases**,
   Q&A, guest posts, tech news. Delivered since: two articles.
2. **The genre that already works here**: the srcset post
   (`src/content/posts/image-srcset-and-sizes-attributes.mdx:35`) says "I
   couldn't find a clear and definitive explanation … so I decided to test
   and explain them myself" — and ships recorded browser-behavior videos
   (`src/assets/videos/{chrome,firefox}_srcset_test.mp4`). That is original,
   tested, un-commoditizable content. The format is the asset.
3. **Topic asymmetry**: 6 topics defined (`src/content/topics/*.json` —
   Astro, CSS, HTML, LeetCode, React, TypeScript); only Astro (1 post) and
   HTML (2 posts) have any content. Four empty topic pages on a live site
   read as abandonment.
4. **Un-mined build material**: this repo's own engineering — hybrid SSG +
   one SSR search route with Netlify durable-cache tuning
   (`src/pages/search.astro:31-48`), a build-time DB sync with orphan
   cleanup (`src/db/sync/buildSync.ts`), a JSON-LD `@graph` refactor (the 4
   commits before `1fce5b5`), an ESLint-enforced service-layer boundary —
   plus the audit in `plans/` that found a real data-loss bug (plan 003).
5. **A series engine already declared**: the Task Manager project
   (`src/data/projects.ts`) is "an incremental frontend laboratory built
   around a reusable task-management backend … frontend implementations are
   developed progressively to explore different patterns, libraries and
   design approaches" — i.e., a controlled-variable comparison series
   waiting to be written.
6. **Dead-end gateway — partly addressed on 2026-08-08 (`fb28acb`)**: the
   homepage now has a `Selected projects` block and CTAs into
   `/my-projects` and `/blog`, and project cards link to live sites and
   landing pages, not only GitHub. What is still missing is the other
   direction: no post references a project, and no project links to a post
   explaining it. That link is what turns the projects page into a gateway.

## Steps

### Step 1: Create `docs/content-roadmap/content-roadmap.md`

Standard repo frontmatter (`created`/`updated`/`summary` — see CLAUDE.md).
Contents:

**a. Editorial line** (one paragraph to pin the "is common stuff pointless?"
answer): every post must contain at least one of — a measurement you ran, a
behavior you tested, a system you built, a failure you hit. If a post could
be generated by an LLM without access to your machine, don't write it.
(Model: the srcset post. Anti-model: a generic "what is srcset" explainer.)

**b. Topic decision** — pick one per topic and record it:
- Astro — KEEP (has content, and item 4's backlog feeds it).
- HTML — KEEP (2 posts).
- TypeScript / CSS — KEEP only with a committed first post in the backlog;
  otherwise PRUNE (delete the topic JSON; topic pages regenerate).
- React — PRUNE unless the D3 series (below) starts with React.
- LeetCode — KEEP only if step 1c's pipeline post gets scheduled; else PRUNE.
  (Pruning = deleting `src/content/topics/<x>.json`; the build sync's topic
  orphan cleanup removes the DB row — after plan 003 lands, safely.)

**c. Backlog — 10 concrete posts, each grounded above** (adjust titles, keep
the substance; ordered roughly cheapest-first):
1. "My blog runs a database it doesn't need — and why I'd do it again"
   (build-time Turso sync architecture, evidence item 4).
2. "One SSR page on an otherwise static site: caching /search on Netlify's
   CDN" (durable cache + `Netlify-Vary`, item 4; write AFTER plan 008's
   investigation — its findings are the post's content).
3. "I let an AI audit my blog and it found a bug that deletes my database
   rows" (plans 001-012 of this repo; the buildSync orphan-cleanup bug).
4. "JSON-LD @graph on a real site: what changed in my search snippets"
   (the recent refactor commits; include Search Console before/after —
   requires waiting a few weeks for data: schedule last).
5. "Enforcing architecture with ESLint: no DB access outside the service
   layer" (the flat-config rule this repo uses).
6. "Task manager, same backend, frontend #1: React" — series opener (item 5;
   each subsequent frontend is another post).
7. "Frontend #2: Astro (yes, for an app)" — series continuation with real
   comparison numbers (bundle size, LoC, time-to-feature).
8. "What building a CLI templater taught me about inquirer and Bun"
   (CLI Templater project card → its showcase post).
9. "A LeetCode problem where my first three approaches were wrong" (LeetCode
   repo; only if topic kept — the failure-narrative format survives LLMs).
10. "Two years of building a blog before writing on it: what I'd cut" —
    honest retrospective; the welcome post is the foil.

**d. Cadence commitment** — realistic, owner-set (e.g. one post/month). The
roadmap doc records it; the git history enforces honesty.

**Verify**: file exists with frontmatter, an explicit KEEP/PRUNE decision per
topic, ≥ 8 backlog entries each citing its evidence, and a cadence line.

### Step 2: Cross-link projects and posts (decision only, here)

Record in the roadmap doc the linking rule: every project gains a "read the
story" link once its showcase post exists (posts 6-8 above), and every
showcase post links back to `/my-projects`. Since `fb28acb` the project data
lives in `src/data/projects.ts` and already carries an optional
`secondaryLinks: { label, href }[]` (rendered by
`src/components/card/ProjectGrid.astro` outside the card, so no nested
anchors) — the "read the story" link is one entry in that array, no
component change needed. Wiring it is executed when the first showcase post
ships — NOT under this plan (no code edits here).

**Verify**: roadmap doc contains the rule and names the first candidate post.

### Step 3: Prune or commit (execute the topic decision)

If any topic was marked PRUNE: delete its JSON from `src/content/topics/` in
a separate commit ONLY after plan 003 has landed (before plan 003, topic
deletion exercises the unguarded orphan-cleanup path against prod on the next
build — see plan 003's Why). If plan 003 hasn't landed, record the pruning as
BLOCKED-on-003 in the roadmap doc instead of deleting.

**Verify**: either topics deleted (post-003) or a BLOCKED note in the doc.
